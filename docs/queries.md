## 📝 ПРИМЕЧАНИЯ И ОСОБЕННОСТИ

### 7.1. Распознавание названий с опечатками (Fuzzy Matching)
Система поддерживает **нечеткий поиск** (fuzzy matching) для названий спектаклей и атрибутов:
- Можно писать с опечатками: "Кормен" вместо "Кармен", "Тре товарища" вместо "Три товарища"
- Система автоматически найдет наиболее похожее название
- Работает для:
  - Названий спектаклей при постановке лайков/дизлайков
  - Названий театров при фильтрации
  - Жанров и других атрибутов

**Примеры:**
- "Поставь лайк Кормен" → найдет "Кармен"
- "Покажи спектакли в театре Пушкин" → найдет "Театр им. Пушкина"
- "Найди оперы" → найдет "Опера" (даже с опечатками)

### 7.2. Лингвистические переменные для длительности
Система использует **лингвистические переменные** для работы с длительностью постановок:
- Вместо точных числовых значений можно использовать естественные описания
- Диапазоны автоматически вычисляются на основе статистики данных (процентили)
- Поддерживаются термы: очень не длинные, недлинные, не длинные, не очень длинные, средней продолжительности, длинные, очень длинные

**Примеры:**
- "Покажи все не очень длинные постановки" → фильтрует постановки до 50 процентиля длительности
- "Найди длинные спектакли" → фильтрует постановки от 75 процентиля длительности
- Можно комбинировать с другими фильтрами: "Покажи все не очень длинные постановки в жанре Театр"

### 7.3. ID можно указывать числом или названием спектакля
- "Поставь лайк 3" или "Поставь лайк Кармен"
- "Лайк 3" или "Лайк Кармен"
- Работает даже с опечатками в названиях

### 7.4. Система понимает естественный язык
- Можно комбинировать несколько действий в одном запросе
- Можно использовать разные формулировки
- Система автоматически определяет намерение пользователя

### 7.5. Фильтры применяются к полному набору данных
- При фильтрации система всегда начинает с полного набора спектаклей
- Можно комбинировать несколько фильтров в одном запросе
- Фильтры применяются последовательно с логикой AND

### 7.6. Рекомендации обновляются автоматически
- После добавления/удаления лайков/дизлайков рейтинг обновляется автоматически
- Система учитывает все активные фильтры при расчете рекомендаций
- Рекомендации основаны на многомерных метриках схожести

### 7.7. Система поддерживает откат
- Можно откатить последнее действие командой "шаг назад" или "назад"
- История хранит до 20 последних действий
- Откат работает для: лайков, дизлайков, фильтров, сброса

### 7.8. Распознавание жанров
- Система распознает: оперы, мюзиклы, балет, театр, комедия
- Можно писать: "Покажи все оперы и мюзиклы"
- Поддерживается множественное число: "оперы", "мюзиклы"

### 7.9. Комбинированные запросы
- Можно ставить несколько лайков/дизлайков и сразу получить рекомендации
- Формат: "Поставь лайк X, дизлайк Y. Что порекомендуете?"
- Можно комбинировать фильтры: "Покажи все оперы с рейтингом выше 8"

### 7.10. Вывод таблицы
- Таблица отображает: ID, Название постановки, Жанр, Рейтинг, Длительность (мин), Театр
- Длительность отображается во всех таблицах (отфильтрованные спектакли, текущие спектакли)

## 🔧 ТЕХНИЧЕСКИЕ ДЕТАЛИ

### Поддерживаемые колонки для фильтрации:
- **Жанр** (с fuzzy matching)
- **Театр** (с fuzzy matching)
- **Стиль** (с fuzzy matching)
- **Язык исполнения** (с fuzzy matching)
- **Целевая аудитория** (с fuzzy matching)
- **Режиссер** (с fuzzy matching)
- **Рейтинг** (числовые операторы: >, <, >=, <=, ==)
- **Длительность (мин)** (числовые операторы или лингвистические термы)
- **Количество антрактов** (числовые операторы)
- **Платный?** (бинарный: да/нет)
- **Семейный?** (бинарный: да/нет)
- **Для детей?** (бинарный: да/нет)

### Операторы для числовых полей:
- `выше` / `больше` → `>`
- `ниже` / `менее` / `меньше` → `<`
- `до` → `<=`
- `после` / `от` → `>=`
- `равен` / `в` / `идут в` → `==`

### Логические операторы:
- `и` → AND (объединение фильтров)
- `или` → OR (альтернативные фильтры)
- `а` → AND (объединение фильтров)

## 📚 ДОПОЛНИТЕЛЬНАЯ ИНФОРМАЦИЯ

Система использует:
- **Морфологический анализ** (pymorphy2) для нормализации текста
- **Синтаксический анализ** (spaCy) для извлечения структуры предложений
- **Нечеткий поиск** (rapidfuzz/fuzzywuzzy) для обработки опечаток
- **Лингвистические переменные** для работы с нечеткими критериями
- **Многомерные метрики схожести** для расчета рекомендаций
- **Дерево критериев** (CriteriaTree) для эффективной фильтрации

Все компоненты работают с **graceful degradation** - если опциональные библиотеки недоступны, система продолжает работать с ограниченной функциональностью.
